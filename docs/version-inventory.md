# 同一项目的版本盘点与归档建议

本次对各版本 `product/backend` 与 `product/frontend/src` 的源文件逐一计算 SHA256；不将运行库、视频、商业材料或缓存当作代码重复项。

| 版本 | 应用源文件 | 与 V3.1 同路径同字节 | 主要身份 |
| --- | ---: | ---: | --- |
| V1 | 15 | 2 | 初版本地能源流程与基础界面 |
| V2 | 20 | 10 | UCI 小时级本地工作台、滚动评测、风险回放及证据闭环 |
| V3 | 43 | 35 | 原生15分钟、PV/月需量、公开跨源评测、运行库与多站点独立队列 |
| V3.1 | 46 | 46 | 本机证据解读、自有模型设置；延续 V3 冻结科学结论 |

V3 中没有仅它存在而 V3.1 缺失的上述应用路径；但 8 个同路径源文件不同，不能把 V3 当作字节完全重复。V1 仍有独有的 `Charts.tsx`；V2 有 `Charts.tsx`、`DataIntake.tsx`、`Pages.tsx`、`Reliability.tsx`、`configIdentity.ts`、`controls.tsx` 等旧架构路径，不能用“最新版文件更多”推断历史代码已全部归档。

建议一个 `nengce-pilot` 仓库作为项目入口，当前开源整理版在主分支。旧版代码另经敏感信息核对后，用清晰的历史分支/tag 或独立源码档保留；不为同一项目重复创建四个仓库，也不把当前代码标成旧版本原始提交。现有 `v2-to-v3.md`、`v3-to-v3.1.md` 保留原变更与失败边界。

本次首先交付 V3.1 核心代码、许可公开研究数据和明确的 Pages 只读案例，没有宣称旧版全部资产已迁移。旧源码差异、私人运行、DPAPI配置、经营预算、原影片与其他材料继续保留本地；未取得独立再分发权的文献也未公开。**V1/V2/V3/V3.1 原目录均暂不可据此删除。**
