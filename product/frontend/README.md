# 能策 Pilot V3.1 · 光储决策工作台

React 19 + TypeScript + Vite。浏览器只访问同源本机 `/api/v3`；不直接连接模型平台、设备或在线字体。计算和证据均来自后端。

## 运行

已编译界面由 `product/frontend/dist` 提供。最终用户只需按项目启动脚本启动 Python 服务，无需安装 Node。

开发与验证：

```text
npm ci --no-audit --no-fund
npm run build
npm test
```

`npm run dev` 仅监听 127.0.0.1，代理至 V3.1 的 `http://127.0.0.1:8003`。依赖版本由 package-lock.json 锁定；运行依赖只有 React/React DOM，无外部 CDN。

## 实际接口与功能

- 数据目录：读取真实 `/datasets` 元数据，支持搜索、公开/私人筛选、适用范围、原生间隔、原始质量/指纹。`/datasets/{id}/quality` 提供跳变、零值、无效值与未观测线索、阈值和原始行。通道不完整且 scope.dispatch=false 的样本只能审查。
- 私人 CSV：本机文件或文本，明确单位、15/60 分钟、时区、可选 PV 列及数据授权；上传至同源本机 `/datasets/import`。不私自插补。服务端原始行错误完整显示。私人导入默认禁止在线助手发送。
- 参数：容量、功率、SOC、效率、吞吐代理、电价、24/96 点日内电价、月需量单价、日期与压力情景。草稿与冻结结果分开保存，可查看变更。助手只能建议草稿，不能自动运行。
- 回放：主图按容器宽度适配 1440/1280/390，支持策略、日期、键盘时段、负荷/光伏/预测/购电/充放电/SOC 联动、最大裁剪定位、每日风险热条和逐时数值。图表只读后端序列，未知值显示“—”。
- 预测：开发验证与当前回放分列；显示实际模型、选择原因、负结果，以及独立光伏选模说明。公开 2018 年 12 月明确标为历史回归。
- 费用：八策略实际执行构成、月账、裁剪及计划差、R1/R2 候选关卡。分段归因为 B1−B0、N1−B1、L1−N1；B2 是开发规则选定策略，不按当前结果临时换赢家。
- 需量：未启用需量时明确标签；启用但原生间隔/完整月不足时保留 null 和已知小计，不将 null 当 0，不算完整收益。每日及逐时费用仅含能量+吞吐代理，整月需量单列。
- 生命周期：请求即时锁定、响应丢失时复用幂等键、真实服务端进度、取消等终态、失败重试、刷新恢复、前进后退、历史异步读取防竞态、分页、批量压力评估及多站点独立批次。每站默认自身评估首日，支持显式完整协议区间，保留当前需量单价且不合并收益。V2 原始产物迁入时标“只读存档”，下载使用对应 API 记录 ID。
- 助手：默认本机证据解读，明确标识“无语言模型”，支持已实现的费用、比较、风险、来源和参数查询及追问；超范围会明确说明。本机模式可用于私人结果，不外发。在线语言模型由用户主动选择，支持自由提问、追问、异步状态、取消、持久会话、引用定位和草稿建议；试用业务验收局限持续展示，不能将本机规则查询算成语言模型成绩。智谱与免费 OpenRouter 备选按后端配置提供，禁止自动切换。已配置不代表在线连接成功。
- 模型设置：助手内可新增、修改、移除 OpenAI 兼容模型配置；支持自有云 API 和 localhost / 回环地址模型。云服务需主动确认自身费用及公开摘要范围。密码输入仅瞬时 POST 至本机后端，提交或关闭面板后清空；不读回密钥，不进入浏览器 localStorage。后端使用当前 Windows 用户加密保存，可单独清除密钥。保存不触发模型调用；用户需明确点击“测试已保存连接”，简短测试不包含业务数据，测试会使用服务账户额度。所有真正模型模式仍只处理公开案例，私人结果仅启用本机证据解读。
- JSON/CSV/HTML 直接链接本次冻结结果导出，前端不另造一份账单。

## 状态与存储

`localStorage` 键前缀为 `nengce.v3.`，保存 draft、run、pending、batch、batch.pending 和按运行区分的 assistant.request。只保存本机用户工作状态，无模型认证信息。

组件按职责拆为 `state/useWorkspace`、`Timeline`、`Overview`、`DatasetCatalog`、`QualityDetails`、`Parameters`、`CostAnalysis`、`ForecastAnalysis`、`History`、`AssistantPanel`、`ModelSettings`、`EvidencePanel`。`api.ts` 集中管理同源接口和规范化配置比较。自有模型配置从 `/api/v3/assistant/providers` 读取，无前端独立副本。

## 验证证据与限制

`tests/ui.test.cjs` 是 DOM/模拟网络回归，使用 `tests/fixtures/result.json`（真实 V3 单日运行复制，来源见 fixture manifest）。可以用 UI_RESULT_PATH 指向另一份真实结果；测试当前以 96 步 15 分钟样本为前提。它覆盖请求生命周期、草稿、负值/null、助手引用与跨运行竞态，但不是浏览器验收。

V3.1 执行与真实 API 浏览器证据写入根目录 `qa/v31/frontend`；保留的 `tests/ui-test-v3.log`、`tests/build-v3.log` 与 `qa/v3` 是原版历史证据。`tests/contrast-review.json` 是指定文本/图形色对的计算审查，并非全页无障碍认证。两轮截图检查发现的问题与处理应以实际最终验收记录为准，不以 DOM 替代。

源时区和午夜推断按数据审计披露。RSF 是电气分项与同站 PV 研究场景，OPSD 单通道不能冒充完整站点。示例费用不是真实客户账单；无售电、资本开支、投资回报、完整寿命或实机控制。助手可用性受免费平台限流影响，核心计算不依赖在线模型。
